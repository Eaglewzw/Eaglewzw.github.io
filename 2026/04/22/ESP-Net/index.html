ESP-Net：在 ESP32 上手撸一个轻量级手写数字识别系统

Posted on 2026-04-22 In 项目实战

摘要： 很多端侧 AI 项目依赖于 TensorFlow Lite Micro 等框架，但在极小内存的 MCU 上，框架本身的开销也不容忽视。ESP-Net 是一个“从零开始”的实战项目，涵盖了从 PyTorch 训练、Int8 量化到手写 C++ 推理算子并部署至 ESP32 (WT32-SC01) 触摸屏的全过程。

1. 项目简介 (Overview)

ESP-Net 旨在展示如何在资源受限的微控制器上实现高性能的神经网络推理。项目选择经典的手写数字识别（MNIST）作为切入点，但不同于简单的仿真，它提供了一个完整的硬件交互界面：用户在触摸屏上书写，ESP32 实时给出识别结果及其概率分布。

🌟 核心卖点：

  • 全栈开发：从数据采集、GPU 训练到模型压缩、嵌入式固件编写。
  • 自研推理引擎：不依赖三方库，手写 nn_ops.cpp，深入理解卷积、池化、全连接的底层实现。
  • Int8 定点量化：通过对称量化技术，将权重和激活值压缩至 8 位，极大降低内存占用。
  • 交互式 UI：基于 LovyanGFX 打造酷炫的技术感界面，支持实时概率条形图展示。

2. 技术架构 (Architecture)

2.1 神经网络模型

为了兼顾速度与精度，我设计了一个轻量级的 CNN 架构：
Input(28x28x1) -> Conv2D(8, 3x3) -> BN -> ReLU -> MaxPool -> Conv2D(16, 3x3) -> BN -> ReLU -> MaxPool -> Flatten -> Dense(64) -> Dense(10)

2.2 模型训练与优化 (train_mcu.py)

  • 数据增强：引入了 ±10° 旋转、随机缩放和平移，提高模型在非标准书写下的鲁棒性。
  • 权重量化：训练完成后，将 FP32 权重映射为 Int8 范围，并导出为 C 语言头文件 model_weights.h。

2.3 嵌入式推理实现 (nn_ops.h)

在 ESP32 端，我实现了以下核心算子：

  • nn_conv2d_same：支持 Same Padding 的 3x3 卷积。
  • nn_batchnorm：将 BN 层参数融合进卷积层的 Scale 和 Bias 中，实现零运行时开销。
  • nn_maxpool2d：2x2 最大池化。
  • nn_dense：带 Softmax 激活的全连接层。

3. 性能表现 (Benchmarks)

3.1 训练效果

模型在 MNIST 测试集上表现稳健，通过混淆矩阵可以看到其对易混淆数字（如 4 和 9）的识别处理得非常好。

训练曲线 混淆矩阵 错误样本分析

3.2 硬件推理指标 (测试平台: WT32-SC01)

  • 推理延迟：约 20-40ms（肉眼几乎无延迟）。
  • 内存占用：激活值缓存（Double Buffer）仅占用约 31KB 内部 DRAM。
  • 存储空间：Int8 权重文件远小于 100KB。

5. 快速上手 (Getting Started)

步骤 A：训练与导出

步骤 B：固件烧录

  1. 使用 VS Code 打开 LVGL8-WT32-SC01-Arduino 文件夹（需安装 PlatformIO 插件）。
  2. 将生成的 model_weights.h 拷贝至 src/ 目录。
  3. 连接开发板，点击 Upload。

6. 总结

ESP-Net 不仅仅是一个识别数字的 Demo，它是一套完整的从算法到硬件的落地方法论。它证明了在不依赖复杂框架的情况下，通过合理的量化与算子优化，即使是 ESP32 这种“低功耗”芯片也能拥有强大的端侧感知能力。
