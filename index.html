ESP-Net：在 ESP32 上手撸一个轻量级手写数字识别系统

Posted on 2026-04-22 In 项目实战

摘要： 很多端侧 AI 项目依赖于 TensorFlow Lite Micro 等框架，但在极小内存的 MCU 上，框架本身的开销也不容忽视。ESP-Net 是一个“从零开始”的实战项目，涵盖了从 PyTorch 训练、Int8 量化到手写 C++ 推理算子并部署至 ESP32 (WT32-SC01) 触摸屏的全过程。

1. 项目简介 (Overview)

ESP-Net 旨在展示如何在资源受限的微控制器上实现高性能的神经网络推理。项目选择经典的手写数字识别（MNIST）作为切入点，但不同于简单的仿真，它提供了一个完整的硬件交互界面：用户在触摸屏上书写，ESP32 实时给出识别结果及其概率分布。

🌟 核心卖点：

  • 全栈开发：从数据采集、GPU 训练到模型压缩、嵌入式固件编写。
  • 自研推理引擎：不依赖三方库，手写 nn_ops.cpp，深入理解卷积、池化、全连接的底层实现。
  • Int8 定点量化：通过对称量化技术，将权重和激活值压缩至 8 位，极大降低内存占用。
  • 交互式 UI：基于 LovyanGFX 打造酷炫的技术感界面，支持实时概率条形图展示。

2. 技术架构 (Architecture)

2.1 神经网络模型

为了兼顾速度与精度，我设计了一个轻量级的 CNN 架构：
Input(28x28x1) -> Conv2D(8, 3x3) -> BN -> ReLU -> MaxPool -> Conv2D(16, 3x3) -> BN -> ReLU -> MaxPool -> Flatten -> Dense(64) -> Dense(10)

2.2 模型训练与优化 (train_mcu.py)

  • 数据增强：引入了 ±10° 旋转、随机缩放和平移，提高模型在非标准书写下的鲁棒性。
  • 权重量化：训练完成后，将 FP32 权重映射为 Int8 范围，并导出为 C 语言头文件 model_weights.h。

2.3 嵌入式推理实现 (nn_ops.h)

在 ESP32 端，我实现了以下核心算子：

  • nn_conv2d_same：支持 Same Padding 的 3x3 卷积。
  • nn_batchnorm：将 BN 层参数融合进卷积层的 Scale 和 Bias 中，实现零运行时开销。
  • nn_maxpool2d：2x2 最大池化。
  • nn_dense：带 Softmax 激活的全连接层。

3.1 训练效果

模型在 MNIST 测试集上表现稳健，通过混淆矩阵可以看到其对易混淆数字（如 4 和 9）的识别处理得非常好。

3.2 硬件推理指标 (测试平台: WT32-SC01)

  • 推理延迟：约 20-40ms（肉眼几乎无延迟）。
  • 内存占用：激活值缓存（Double Buffer）仅占用约 31KB 内部 DRAM。
  • 存储空间：Int8 权重文件远小于 100KB。

6. 总结

ESP-Net 不仅仅是一个识别数字的 Demo，它是一套完整的从算法到硬件的落地方法论。它证明了在不依赖复杂框架的情况下，通过合理的量化与算子优化，即使是 ESP32 这种“低功耗”芯片也能拥有强大的端侧感知能力。

GD-Net：深度优化边缘检测，仅 1M 参数的 MCU 级目标检测框架

Posted on 2026-04-22 In 项目实战

摘要： 在嵌入式设备（如 MCU、IoT 终端）上实现高精度的实时目标检测一直是工业界的难题。传统的 YOLO 模型即便经过“微缩”也难以满足 SRAM 仅数百 KB 的限制。GD-Net 通过集成 MCUNet (TinyNAS/ProxylessNAS) 搜索出的极致骨干网络，结合 Decoupled Head 与 SPPF 技术，成功将 YOLOv3 架构压缩至 1.016M 参数，FLOPs 仅 651M，实现了在低功耗边缘侧的丝滑运行。

1. 为什么需要 GD-Net？ (Introduction)

在无人机避障、工业自动化巡检以及智能家居场景中，我们往往需要在极低功耗的微控制器（MCU）上运行视觉算法。标准的 YOLOv5n 仍有约 1.9M 参数，对于内存敏感型设备来说依然过大。

GD-Net (Generalized Detection Network for Edge) 诞生的初衷，就是要在 <5MB 磁盘占用 和 <1MB SRAM 占用 的极端条件下，交付可商用的检测性能。

🚀 核心技术亮点：

  • 硬件感知的 NAS 骨干： 采用由 TinyNAS 搜索出的 MCUNet 主干，直接针对硬件延迟进行优化。
  • 解耦检测头 (Decoupled Head)： 将分类与定位任务拆分，不仅提升了 2%-3% 的 mAP，还加快了模型的收敛速度。
  • 高效特征融合： 使用改进的 PANet 结构配合 SPPF (Spatial Pyramid Pooling - Fast)，在不显著增加计算量的情况下扩大了感受野。
  • 全链条 TFLite 支持： 原生适配 Int8 量化流程，模型体积可进一步压缩至 1.2MB。

2. 核心架构深度解析 (Architecture)

GD-Net 的设计哲学是模块化与高效化。它通过重新平衡 Backbone 与 Head 的参数比例，确保了特征提取的高效性。

2.1 骨干网络：MCUNet 的力量

我们摒弃了传统的 Darknet-53 结构，引入了 ProxylessNAS 搜索出的轻量级算子。针对不同资源限制的 MCU，GD-Net 支持多种规格：

  • GD-Net-S (Small): 基于 mcunet-256kb-1mb，适配 512KB SRAM 设备。
  • GD-Net-M (Medium): 精度与速度的最佳平衡。
  • GD-Net-L (Large): 针对边缘计算卡（如 Jetson Nano/ESP32-S3）设计的增强型。

5. 总结与展望

GD-Net 证明了通过结合 NAS（神经架构搜索）与先进的检测器设计（YOLOv3-PAN），我们完全可以在微米级的算力上实现高性能的视觉感知。

未来的改进方向：

  1. 集成更先进的 RepVGG 重参数化技术。

Drone-10k：一个包含1万张高清目标的无人机检测数据集

Posted on 2025-12-15 Edited on 2025-12-16 In 技术分享

摘要： 分享一个自制的无人机检测数据集 Drone-10k。数据量大约 10,000 张，融合了西湖大学公开数据与个人采集数据，主要包含三类无人机机型 DJI Mini、DJI Air和大疆精灵。核心亮点是目标尺寸均 >16x16 像素，剔除了极小噪点。如果有需要的同学可以下载使用，希望对大家有用。

1. 为什么做这个数据集？

起初，这其实是我的硕士毕业设计课题——《小目标无人机检测与拦截控制研究》的一部分。在完成这个课题的过程中，我发现了一个很尴尬的现实：

  1. 现实与数据的割裂： 现实生活中，我们要防范或拦截的绝大多数都是大疆（DJI） 这种消费级无人机。
  2. 开源数据的匮乏： 但翻遍了市面上的公开数据集，很多都是大型客机和零散的不知名的无人机，真正包含高清大疆无人机的数据少之又少。

为了解决这个问题，让模型真正具备实战能力，我和我的学弟学妹们，一点点采集、清洗、融合了这份数据，这里也特别感谢他们的帮助。

关于数据的清洗与重采样

必须说明的是，我们原始采集的数据量其实高达 50,000 张。但在分析阶段我们发现，自采数据虽然清晰，但受限于大疆无人机设备，存在无人机型号和类别单一的问题。

为了保证数据集的泛化性和平衡性，我们没有简单地堆砌数量，而是采取了一定的筛选策略：

  1. 去噪： 对自建库和西湖大学开源数据执行同样的预处理，剔除所有小于 16*16 像素的无效噪点。
  2. 重采样： 从自建库和西湖大学筛选后的数据库中，随机下采样（Under-sampling） 了 10,000 张 最具代表性的样本。

最终，我们得到了这份去粗取精、总量约 1万张 的 Drone-10k 数据集。

核心特性：

  • 📸 数据量大： 包含 10,000+ 张真实场景图片。
  • 🔍 拒绝模糊： 严格筛选标准，所有标注目标的尺寸均在 16×16 像素以上（有效特征区域）。
  • 🌍 场景丰富： 涵盖天空、城市、野外、逆光等多种复杂环境。


图1：Drone-10k 数据集概览（1000张样本的密集阵列展示）。每一个方格都是一个清晰的无人机目标，而非模糊的黑点。

2. 数据可视化分析

为了证明数据的质量，我们对 1w 张标注数据进行了深度的统计分析。

2.1 目标尺寸分布：清晰可见的细节

很多检测模型（如 YOLO 系列）对微小目标（<16px）极其敏感且难训练。我们将所有目标的宽(Width)和高(Height)绘制了密度散点图：


图2：目标尺寸分布图（密度着色）。

  • 分析： 从图中可以看出，数据集中绝大多数样本都落在中等尺寸区间。虽然存在长宽比的变化，但几乎没有极小尺寸的噪点样本。这保证了卷积神经网络（CNN）能够提取到有效的纹理特征，而不仅仅是学习背景噪声。

2.2 空间分布：拒绝“中心过拟合”

为了验证拍摄时是否存在严重的偏差，我们绘制了所有目标在画面中的位置热力图：


图3：目标位置热力图。

  • 分析：
    • 中心热点： 黄色区域显示存在一定的摄影师中心跟随习惯，符合真实应用场景。
    • 边缘覆盖： 紫色区域广泛覆盖了画面的四周角落。这意味着数据集包含大量无人机飞出视野中心、位于边缘的困难样本。
    • 结论： 使用本数据集训练的模型，将具有更好的鲁棒性，不会养成“只看画面中间”的坏习惯。
